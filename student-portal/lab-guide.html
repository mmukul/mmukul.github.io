NextGen DevSecOps Lab — One-Command Setup

Your Local Lab runs on your own Linux VM or host. A web page cannot directly execute operating-system commands on your computer. The secure “one-click” experience here is therefore a single copy-and-run command in your Linux terminal; the command downloads and verifies the installer before running it.

Before you start

  • Use an Ubuntu/Debian or Rocky/RHEL/Alma/Fedora/CentOS Linux VM.
  • Use a VM with internet access and sudo/root privileges.
  • Recommended: 4+ CPU, 8 GB RAM and 30+ GB free disk for a comfortable training lab.

Verified one-command installer

curl -fsSL https://mmukul.github.io/nextgen-devsecops-setup.sh -o /tmp/nextgen-devsecops-setup.sh && echo "a6584c0ef29433f1f1e64b6378e12eaf0c718f09149e17173753605a226386b7 /tmp/nextgen-devsecops-setup.sh" | sha256sum -c - && sudo bash /tmp/nextgen-devsecops-setup.sh
⬇ Download Installer
1. CopyCopy the command above.
2. RunOpen the VM terminal, paste it and press Enter. Enter your sudo password if requested.
3. VerifyWait for “Lab installation complete”, check the exit status, then check Jenkins at http://localhost:8080 from the VM.

What the installer installs

Java 21, Maven, Docker, Jenkins, Trivy, Checkov, InSpec and OWASP Dependency-Check.

Jenkins: Current Jenkins Linux packages require Java 21 or later. The installer uses Java 21 and the current Jenkins LTS repository signing key.
Security: Never paste Supabase service-role keys, Turnstile secrets, UPI/payment credentials, cloud credentials or production API keys into the terminal or lab.

If setup fails

  1. Check that the installer URL returns the shell script, not an HTML 404 page. If it does not, publish the repository root to GitHub Pages and confirm nextgen-devsecops-setup.sh is at the published root.
  2. If checksum verification fails, stop. Refresh this page and redeploy the matching installer and guide together. Do not bypass verification.
  3. If a package installation fails, copy the terminal error and send it to the trainer with your Linux distribution and version.

After installation

  1. Open Jenkins on the VM: http://localhost:8080.
  2. On the VM, retrieve the initial Jenkins password using sudo cat /var/lib/jenkins/secrets/initialAdminPassword. If accessing the VM remotely, use its reachable IP address and ensure port 8080 is accessible only to authorized users.
  3. Return to My Assigned Labs in the Student Portal.
